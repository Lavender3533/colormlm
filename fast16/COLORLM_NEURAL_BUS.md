# ColorLM Neural Bus：长期架构主文档

更新日期：2026-07-31

本文档是从“最终方向定为 ColorLM Neural Bus”开始形成的权威设计记录。旧实验文档可以保留，
但后续路线、实现优先级和术语以本文档与根目录 `PROJECT_STATE.md` 为准。

## 一句话目标

构建一个优先落在15–30GiB、能力收益明确时可扩到50–70GiB的本地单模型，在RX 5700 XT
8GiB显存和32GiB内存上运行，以快速循环主干维持基础语言能力，通过隐藏状态神经路由按需
调用跨模型专家胶囊和连续神经岛，并用GPU/RAM/SSD三级分页承载远大于显存的逻辑专家容量。

## 当前决定

- 当前生产基线固定为ColorLM v6，任何新机制关闭时必须精确退回v6。
- 当前研发顺序改为：推理加速 → 正确专家分页 → Neural Bus最小原型 → 更多供体。
- Claude Code接入已经可用，但暂时冻结，不围绕Claude接口优先开发。
- Coder连续四层神经岛和v18真实深层激活桥已经完成。当前正式研究候选为
  `ColorLM-v18-Deep-Activation-Island`；下一质量门是补足独立配对状态并验证真实工具回合，
  通过后再决定扩为L40–L47或引入第二供体岛。
- 新供体按`V17_DONOR_SCREEN.md`筛选，通过可运输性和互补能力门后才下载所需Range，
  不下载整模碰运气；50–70GiB是能力成立后的容量上限，不是堆模型目标。
- 不用直接替换、随机拼层、关键词路由或长时间训练伪装融合能力。
- 所有新checkpoint先过固定短表；不刷与编程和Agent目标无关的长榜。

## 总体结构

```text
输入
  ↓
Fast Spine：快速循环主干
  ↓
2048维公共神经工作空间
  ↓
Neural Bus路由站
  ├─ 继续原生v6安全路径
  ├─ 调用Coder-Next L44–L47连续神经岛
  ├─ 调用Coder-Next残差专家胶囊
  ├─ 调用Kimi K3前端/Agent胶囊
  ├─ 调用GLM通用代码/工具胶囊
  ├─ 重复当前纠错块
  ├─ 跳过低收益计算
  └─ 结束并输出
```

路由必须读取当前隐藏状态、层地址、计算预算和误差信号。它是神经门控，不读取生成后的
关键词做分类，也不是外部多模型工作流。

## 核心模块

### 1. Fast Spine

利用现有混合线性注意力/循环状态建立每token必经的轻量主干。主干先产生候选隐藏状态，
重型专家只在预测误差或不确定度较高时参与修正。

### 2. Corrective Expert Bus

外来专家不再替换原生专家，而是提供可关闭的残差：

```text
h_next = h_native + alpha(state, budget) * delta_donor
```

当alpha为0时结果必须退回v6。该设计直接修复v8“引入Coder专家同时损伤原能力”的问题。

### 3. Neural Slice ABI

所有供体切片对外编译成统一的 2048 维接口，但内部宽度不再强制统一为 512：

```text
输入宽度 2048
内部配置 micro-512 或 donor-native macro
输出宽度 2048
附带入口norm、出口scale、供体层、量化类型和坐标运输哈希
```

`micro-512`用于低成本机制探针；`donor-native macro`用于保留完整供体函数路径。
跨宽度供体先做残差坐标运输。第一颗 K3 宏胶囊保留其完整
`2048 -> 3584 -> 3072 -> 3584 -> 2048` latent expert 路径，不再为了追求 MiB 级体积
预先删到 512 神经元。确认能力后再按64/128神经元分页。

### 4. Layer-Free Expert Capsule

专家不永久绑定某一层。每个胶囊增加层地址嵌入和小型低秩入口/出口适配器，使同一专家可在
不同路由站工作。先建立两个路由站验证，再扩展到约十个站，不一开始改成完全自由图。

### 5. Demand-Routed Synaptic Paging

- GPU hot：每层16–32个高频专家。
- RAM warm：最近使用的量化专家页。
- SSD cold：GGUF/CLM中的冷专家页。
- miss必须等待正确专家或走原CPU专家，绝不映射到槽位0。
- 先做专家级分页，再研究每64或128神经元一页的二级分页。

### 6. Hierarchical MoE

路由分两级：先选专家，再在专家内部选择神经元页。当前专家有512个中间神经元；K3专家
有3072个中间神经元，可通过三因子重要度和任务激活筛到512个，再按64神经元分组。

### 7. Expert Bidding

每个专家保存一个极小能力指纹，先估计自己对当前误差的修正收益。总线路由器根据收益、
加载成本和时间预算选择专家，不需要先加载完整专家权重。

### 8. Error-Driven Adaptive Compute

每次模块更新后计算隐藏状态变化、输出熵、预测一致性和验证器分数。误差低时结束，误差高时
继续调用规划、代码或审查胶囊。简单token少算，架构与调试token多算。

### 9. Virtual Experts

大量专家共享公共骨架，只存压缩差分：

```text
W_virtual = W_base + delta_coder + delta_kimi + delta_task
```

现有q3_g64容器可作为差分格式起点；最终由Vulkan内核在矩阵累加时解码，不物化完整F32。

### 10. Hidden-State Speculation

Fast Spine一次预测未来2–4个隐藏状态，重型专家批量验证。正确则同时接受，错误则从首个分歧
位置修正。这是单模型内部推测执行，不额外加载草稿模型。

### 11. Multi-Timescale Context

- 最近代码：原始token和GPU KV。
- 当前文件：量化KV/RAM。
- 旧文件：符号、函数签名和依赖关系。
- 项目长期状态：循环工作记忆。
- 只有需要时才分页恢复旧token或KV。

上下文扩容晚于核心速度优化；模型声明262K，但当前运行入口只配置32K。

### 12. Layer-Specific Transport

共享token嵌入运输只证明全局残差空间可对齐。最终应建立输入、中层、推理层和输出层运输，
并约束相邻运输矩阵平滑变化。允许1–30秒只训练小桥、层适配器和路由器，大模型权重冻结。

### 13. Continuous Donor Neural Island

当单颗专家或单层完整块无法保留供体算法时，以“一次进入、供体坐标内连续执行、一次退出”接入
连续层段。v17首个实例为Qwen3-Coder-Next L44–L47：三层Gated DeltaNet接一层Full Attention，
每层都保留共享专家和512专家top-10 MoE。循环状态与KV必须归属`llama_context/seq`，不能放在
全局权重对象；冷专家留在host，decode只把精确命中的专家页送入GPU热槽。

## Vulkan与运行时主线

Fast16 Runtime v1先保证同一v6更快、输出不变：

1. 启用已验证的`GGML_VK_SPIN_FENCE=1`。
2. 合并CPU专家与GPU模块之间的fence周期。
3. 融合router、top-k、专家计算和加权求和。
4. 建立正确的热专家槽池和异步下一层预取。
5. 保留ngram自推测，后续加入隐藏状态推测。

已实现Vulkan到pinned host批量读取和Alder Lake IQ3_S gather。当前固定短测的
最高点约`26.26 ± 0.22 token/s`；Neural Bus v1的128-token相邻检查为v6 `20.42`、
总线`21.61 token/s`。绝对速度会随机器状态波动，后续只用相邻A/B做决策。

v17.2为连续岛增加四层各32槽的精确GPU热专家缓存，共约216MiB。160-token短解码从
`4.45`升至`10.41 token/s`（约`2.34x`）；4235-token提示后的短解码从`5.80`升至
`13.39 token/s`（约`2.31x`）。两组均为单次短比较，且prefill路径不使用热缓存，不能把
prompt速度波动或该倍数外推为所有任务的稳定收益。

v17.3给缓存加入逐供体层命中/上传统计，并修正同token LRU epoch。把缓存回调移出专家ID
依赖链虽然表面恢复路由融合，却失去“上传完成后才能remap”的跨后端正确性且实测回归，已否决。
64槽命中率更高但把显存推到约7363MiB并降到`0.89 token/s`，正式配置继续使用32槽。

v18用完整79.67B Qwen3-Coder-Next的L43 `l_out`与ColorLM L35 `attn_residual`拟合真实
深层桥。772个跨词表UTF-8边界配对状态、两个整prompt留出划分均通过；主留出余弦中位数
`0.1951 -> 0.5499`，同原生幅度RMSE比`0.7437`。四层岛权重总量不变，`alpha=0`仍物理
旁路。当前限制是训练状态少于隐藏宽度，未观测正交子空间仍需nullspace先验或更多激活覆盖。

## 已验证事实

- v6：当前能力胜者，12.79GiB，Code8 8/8，工具4/4。
- v7：Coder专家未对齐直接嫁接，路由表现不优于随机轴，失败对照。
- Coder运输：未见token身份恢复率98.54%。
- v8：运输后单专家替换，Code8 7/8，说明直接替换仍会破坏原能力。
- Kimi K3运输：7168→2048，未见token身份恢复率95.42%。
- v6专家库10.70GiB；每层16个热专家的40层槽池约0.669GiB。
- `qwen35moe`精确slot_pool已实现，miss会上传真实专家而不再回落slot 0；但
  `8×28`相邻复核慢约24.6%，因此只保留显式研究开关，Fast16默认关闭。
- v13逐站反事实确认只启用L12 K3优于L12/L28双站；正式模型为12.967GiB的
  `ColorLM-v13-Causal-Sparse-L12`，当前服务是`127.0.0.1:8102/v1`。
- no-op隐藏态、L12条件隐藏态、四状态联合路由和6维实际残差路由均未通过严格任务留出门；
  L28继续封存。探针与失败报告保留，但不得生成生产路由计划。
- v17已在主干L35接入3.514GiB的Coder-Next L44–L47连续岛；三层循环状态使用原生recurrent
  槽`3/7/11`，L47使用原生KV槽`34`，状态随context/sequence管理。4235-token标记取回和新请求
  状态隔离通过。
- v17.2的32槽缓存只在单token decode启用，prefill走完整专家银行；miss等待真实top-10上传，
  不映射到错误专家。短测证明运行路径和提速，尚未证明编程质量高于v6或前沿闭源模型。
- v18已完成真实L35/L43激活采集与跨词表UTF-8边界配对。严格12折LOTO确认12条prompt的
  方向提升全部为正，但中位范数尺度5个唯一切分`0/5`通过，训练集最小二乘尺度也仅`2/5`；
  因此隔离包降为研究复现，正式版保持v17，不进入代码/工具能力短测。
- v18.1只改变欠定Procrustes的零奇异值正交完成：已观测方向保持最优解，未约束自由度选择
  距离旧嵌入桥最近的可逆完成。同一严格门达到LOTO通过、5个唯一切分`5/5`通过，生成
  `runtime-v2`隔离候选；运行级短测通过前仍由v17承担正式入口。
- v18.1运行级短门修复了`read_file`必填参数为空，但独立Rust A/B与v17出现同一种围栏、冗余
  数据结构和截断失败，因此不替换v17。下一能力实验必须改变最终token分布，不能只继续优化
  L35到L44的坐标桥几何指标。

## 明确暂停或否决

- 暂停围绕Claude Code接入继续堆功能；接口已经够用。
- 暂停盲目加入更多完整模型。
- 否决不同模型层按编号直接交替拼接。
- 否决把未命中专家替换成另一个槽位专家。
- 否决把“模型能加载”或模型自述当作能力提升。
- 否决用关键词if/外部检索冒充内部神经路由。
- 否决长时间训练未知目标；只允许小桥和小路由短校准。
