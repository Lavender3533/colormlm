# ColorLM v17 强供体筛选门

更新日期：2026-07-30

## 目的

ColorLM仍可继续融合更强开源模型，但下一阶段不按总参数量或榜单名次堆权重。每个供体只为一个
明确能力槽负责，并且必须以连续神经块进入统一隐藏空间。未通过短反事实门的候选不下载整模、
不进入正式版本，也不占用v17版本号。

## 当前优先级

| 优先级 | 供体 | 目标能力 | 当前动作 |
|---:|---|---|---|
| 1 | Qwen3-Coder-Next L44--L47 | 代码规划、跨文件代码表征 | 利用已有L47资产，补齐前三层形成首个连续四层岛 |
| 2 | GLM-5开源权重 | 工具规划、中文指令、通用推理 | 先核验权重许可、张量索引、连续层Range与llama.cpp算子覆盖 |
| 3 | Kimi K3连续块 | Agent规划、长程状态、前端代码 | 现有孤立宏专家只作候选；重新按连续块审计，不直接再加专家编号 |
| 4 | DeepSeek开源MoE | 代码推理、压缩注意力 | MLA和隐藏宽度迁移成本高，先做张量与坐标可运输性审计 |
| 5 | 小米MiMo开源权重 | 互补代码/Agent能力 | 型号和开放权重需先核实，未核实前不分配磁盘预算 |

## 五个硬门槛

1. **连续性**：优先三到四个相邻层，孤立专家必须证明单独有因果收益才保留。
2. **可运输性**：入口/出口桥必须用深层特征拟合；只凭hidden宽度相同不能视为坐标兼容。
3. **可执行性**：Vulkan已有关键算子，或新增算子成本明确；不能把CPU全量回退当正式方案。
4. **互补性**：在v17 Coder岛已经正确的题上不得回归，并至少修正一个主干稳定失败点。
5. **单位成本**：记录每增加1GiB带来的反事实NLL、任务翻转和token/s变化；无收益权重立即退出。

## 最小准入检查

- 三个固定短前缀做`no-op / donor` next-token NLL对照。
- 一个可编译的多文件代码修改，最多一次构建反馈。
- 一个带必填参数的结构化工具调用，只看参数和停止行为。
- 一次128-token相邻速度检查；不跑长榜，不重复刷随机种子。

## v17装配顺序

```text
ColorLM v6/v13安全主干
  -> 深层特征输入桥
  -> Coder-Next L44--L47连续神经岛
  -> 独立有界KV + 压缩长期记忆
  -> no-op冲突仲裁
  -> 通过准入门的第二供体岛
  -> 局部隐空间循环与停止头
```

首个产物不是“塞满更多模型”的v17，而是一个坐标连续、缓存独立、能被关闭和归因的Coder岛。
这条主线完成后，GLM-5是第二供体首选审计对象；K3、DeepSeek和MiMo保持并列候选。
