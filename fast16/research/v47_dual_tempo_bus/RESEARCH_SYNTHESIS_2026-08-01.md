# v47 在线研究与算法决策（2026-08-01）

## 结论

当前最值得并行推进的不是继续塞 donor，而是两种互补压缩：

1. **语义压缩**：模型生成 150–600 字节 Design Genome，确定性编译成完整网页。它同时减少等待、
   截断、重复函数和三卡片模板回退，是下一次前端体验最可能出现肉眼改善的路线。
2. **计算压缩**：第一个 token 复用 v38，未来 token 使用 rank-64/192 行非自回归草稿，并由 v38
   无损验证。它只在自由滚动接受长度过门后进入 C++。

## 外部证据与本项目采纳方式

### Design2Code

- 论文：https://arxiv.org/abs/2403.03163
- 证据：484 个真实网页的评测显示，前沿模型的主要短板仍是视觉元素召回和正确版式，而不仅是 HTML
  语法。
- 采纳：现有静态分必须补真实栅格/断点检查；IR 要显式编码版式、视觉系统和响应式变换。

### Making Failure Safe

- 论文：https://arxiv.org/abs/2607.00035
- 证据：把自由代码改成 typed JSON、受限模板、规则校验和结构化修复后，可形成确定、可验证且执行期
  零 LLM token 的路径。
- 采纳：编译器直接输出最终页面；不再让 v38 根据 IR 继续自由展开长 HTML。

### WebDesignIter

- 论文：https://arxiv.org/abs/2607.10621
- 证据：前端任务中，持久设计知识比单纯代码图检索、补丁或沙箱验证更重要；论文报告移除设计知识后
  Pass@1 下降 11.40 个百分点。
- 采纳：把版式语法、组件职责、交互和视觉规则做成 Design Genome，而不是只有通用组件列表。

### NanoSpec

- 论文：https://arxiv.org/abs/2605.26444
- 证据：上下文感知动态小词表可把草稿活跃词表缩小 40 倍以上，并减少草稿时间。
- 采纳：保留 native top-32 + recent-96 + train frequent-64 + limit-192；但本项目仍需独立轨迹复核，
  不能外推论文速度。

### Draft-OPD

- 论文：https://arxiv.org/abs/2605.29343
- 证据：只在目标模型固定轨迹上 SFT 会出现 offline-to-inference mismatch，接受长度很快平台；有效训练
  需要在草稿自己诱发的状态和被验证拒绝的位置上学习。
- 采纳：408/408 teacher-forced 覆盖仅为必要条件；新增自由滚动与 rejected-position replay 契约。

### FastEagle

- 论文：https://arxiv.org/abs/2509.20416
- 证据：一次非自回归地产生整段草稿，并以逐层监督抑制误差累积，可避免 N 个未来 token 的 N 次串行
  草稿前向。
- 采纳：v47 优先单次 cascaded block head，不接受四个串行 rank-64 头把草稿延迟重新加回来。

### Mixture-of-Recursions

- 论文：https://arxiv.org/abs/2507.10524
- 证据：共享层递归与 token 级动态深度在从头训练的 135M–1.7B 模型上形成质量/吞吐 Pareto 改善。
- 采纳限制：它不是可直接外挂到冻结 v38 的补丁。当前只保留 256–512 维局部潜在循环，并且必须在
  能力岛已有完整任务净增益后才训练 K=0..4 路由；云端阶段才考虑共同训练共享递归栈。

### WebIGBench

- 论文：https://arxiv.org/abs/2606.00154
- 证据：该工作不是只截屏比较静态页面，而是收集了103个真实复杂网页、5类常见交互和871个独立
  交互动作，并用人工定义的交互路径配合浏览器自动化评测生成代码。
- 采纳：v47 的正式前端门必须把“打开抽屉→修改字段→提交→状态更新→ESC/返回关闭”记成完整
  action trace。单个按钮有 `onclick`、页面看起来丰富或静态分变高，都不能替代流程完成率。

### FlowEval

- 论文：https://arxiv.org/abs/2605.04165
- 证据：生成 UI 的可用性可通过参考网页与候选页面的导航轨迹比较来近似，论文使用包括动态时间规整
  在内的参考相似度，并在小规模专家研究中观察到与人工判断较强相关。
- 采纳：下一版浏览器门记录 `(action, target-role, visible-state, url/dialog-state)` 序列；除硬性的任务
  成功/失败外，再比较候选与冻结参考流程的编辑距离/DTW。这样能区分“最终也完成了但绕了很多无效
  点击”和真正顺畅的交互实现。

### 本轮真实失败样本

- 用户保留的6个历史网页产出已经静态审计：最高76.85，最低67.55；多个版本仍出现恰好三张通用
  卡片、Emoji图标、远程随机图、空链接、假交互、缺少可见焦点与 `prefers-reduced-motion`。
- 采纳：这些样本只作为负约束来源，不作为正教师。训练标签与教师准入必须显式拒绝上述模式；最终
  晋级仍由375/768/1024/1440四档浏览器渲染和完整 action trace 决定。

## 立即停止的误区

- 用 8 条自由文本 IR 训练小 GRU，再把记忆结果说成跨模板能力；
- 用 teacher-forced shortlist 覆盖率宣称推测解码已经加速；
- IR 之后再次调用模型生成数千 token HTML；
- 只抬静态复杂度分，不做真实断点、交互和视觉检查；
- 在没有互补任务证据时继续增加 donor 或胶囊。

## 本地与云端分工

- **8GB/32GB 前期**：v38 + Design Genome 编译器 + 小于256MiB热辅助模块；模型只生成短控制序列。
- **免费云计算后期**：扩大 train-only 轨迹、pointer/copy 解码器、on-policy 草稿训练与共同训练递归栈；
  参数可以增加，但 no-op、无损验证、独立能力门和一次 blind 仍保持不变。
