# ColorLM Dual-Tempo Neural Bus 设计

## 1. 一条总线，两种时间尺度

```text
                             ┌─ 快通道：多 token 草稿 ─ v38 无损验证 ─┐
用户上下文 → v38 共享主干状态 ┤                                      ├→ 下一状态
                             └─ 慢通道：K=0..4 潜在循环 → 能力序列岛 ─┘
```

快通道只减少重复主干前向，不改变最终分布。慢通道只在可自动验证的关键决策上花额外计算，目标是
提高工具、规划、前端和调试的成功率。两条通道共用 v38 的 token、KV、终层 hidden 和验收器，禁止
再启一个完整 donor 常驻显存。

## 2. 快通道：EAGLE-3 式草稿，不复活 v24 n-gram

输入使用 v38 的浅/中/深三处隐藏特征，经小投影融合后直接预测未来 `1..4` 个 token。第一个 token
复用 v38 已经计算出的原生 logits；未来 token 不重复做 `2048×248320` 稠密投影，而使用 rank-64
投影和最多 192 行动态候选。候选优先由原生 top-k、最近上下文 token、工具/语法 token 和 train-only
高频 token 组成；完整低秩行表可放主存，热 8192 行放 GPU。

草稿只能由 v38 自己验证：第一个不一致处立即截断，已接受 token 才进入 KV。这样 shortlist 漏词或
低秩预测错误只损失时间，不损失质量。teacher-forced 候选覆盖只是一项必要条件；草稿头还必须在
自己的自由滚动状态上训练/回放，并把首次拒绝位置重新加入训练。只有候选覆盖率、自由滚动接受
长度和端到端 A/B 三项都通过，才允许改 C++；不能把解析 FLOPs 上界写成已经加速。

离线先计算：

- 平均接受长度；
- 每次草稿计算量与一次 v38 decode 的比值；
- 端到端理论加速下界；
- 长上下文分桶，防止只在短 prompt 上看起来很快。

晋级要求：`alpha=0/草稿关闭` 字节等价；真实相邻 A/B 至少 `+8%`；24 个冻结短门零回归。
此前 v24 n-gram 的回滚不等价和 `-0.72%` 是硬负证据，不能复用其状态管理。

## 3. 慢通道：局部递归，不重复整网

困难度路由器输出 `K∈{0,1,2,3,4}`。递归块只更新一个 256–512 维共享潜在工作区 `z`，不重复
v38 的全部层：

```text
z0 = P · normalize(h_terminal)
z(k+1) = z(k) + MLP(LN(z(k)), context=P·h_terminal)
stop_k = sigmoid(w_stop · z(k))
```

`K=0` 必须是物理 no-op。训练标签来自反事实轨迹：额外循环是否修复完整任务，而不是 hidden 能量、
关键词或生成后的人工印象。平均 `E[K]` 必须受预算约束，简单 token 不为困难 token 买单。

## 4. 能力序列岛

### 4.1 工具岛

一次 terminal hidden 初始化小型 GRU，然后输出完整工具调用短序列。第一版使用 train-only 局部词表，
如果 validation 的 OOV 超过 2%，必须进入 pointer/copy 版本，禁止偷看 blind 扩词表。

### 4.2 前端岛

前端 HTML 太长，不适合由小 GRU 或 v38 自由逐 token 展开。前端岛只输出可验证的 Design Genome
IR，通用编译器直接生成最终 HTML/CSS/JS，不再让 v38 在 IR 后继续写数千 token 代码：

- 闭集的页面身份、版式语法、组件、交互、响应式变换和视觉系统；
- 用户专有文字使用 copy slot/reference，不能要求小岛记住未见 token；
- 至少一个非模板化构图和两项有目的的交互；
- 移动端折叠、无障碍和依赖安全规则；
- 目标长度 150–600 UTF-8 字节，必要时允许到 1200 字节；
- 相同 IR 必须确定性编译为相同页面，编译阶段不再消耗模型 token。

第一阶段由 v38 在有硬长度上界的一行 grammar 下直接产生短 IR，以最快形成教师/可体验闭环；JSON
Schema 漂亮打印和无界 GBNF 列表都已在真实 v38 上发生截断或重复，不能作为正式路径。积累足够的
train-only 成功轨迹后，正式本地路径改为 **Parallel Genome Head**：terminal hidden 经一个共享小投影，
一次并行预测视觉、版式、5个组件角色、4个动作角色和2个响应式角色，不再自回归生成 IR；用户文字
由独立 pointer/copy 槽处理。评测必须覆盖生成、编辑、修复三类，并同时看 HTML 正确性、响应式、
交互、可访问性、外部依赖风险、视觉栅格检查与“三卡片模板”惩罚。

### 4.3 规划/调试岛

输出短动作图、补丁计划或诊断序列。只有单岛在自己的独立门上证明净增益，才允许加入总线路由；
岛之间默认 no-op，不能为了“模型更多”强行融合。

## 5. 训练数据契约

每条任务只采集一次初始 terminal hidden，绑定完整目标 token 序列。禁止把同一任务的 teacher-forced
各 token hidden 当成独立任务，这会把答案前缀泄露给解码器。8 条基础 train 题只足够验证编译器，
不足以证明一个自由文本 GRU 能跨模板泛化；蒸馏前必须仅从 train 家族生成至少 128 条组合/改写轨迹，
并使用闭集语法与 copy slot。validation/blind 的模板、文案和目标都不得用于扩词表或补规则。

```text
record = {
  task_id, group_id, template_cluster_id, split,
  capability, target_mode,
  target_text, target_token_ids,
  capture_record, prefix_sha256
}
```

拆分单位是 `group_id` 和 `template_cluster_id`。训练只看 train；validation 选结构；blind 只在冻结后
执行一次。前端教师数据必须保留需求、最终页面、编辑轨迹和修复轨迹，不能只收漂亮截图。

## 6. 8GB 本地与后期云端

本地阶段：v38 约 12.7 GiB 权重由 Vulkan/CPU 混合承载；草稿头、路由器和单个热能力岛控制在
64–256 MiB，冷岛驻 SSD/内存。云端阶段可以扩大 latent width、能力岛数量、教师数据和基座参数，
但仍保持同一 no-op、独立能力门和按需计算契约。云端不是放弃架构约束，而是把通过的小结构放大。

## 7. 晋级顺序

1. 用 8 条 train 题完成 Design Genome IR 与通用确定性编译器，测端到端墙钟与完整页面成功率。
2. 先让 v38 受有界 grammar 约束生成短 IR；train 闭环稳定后扩成至少 128 条 train-only 轨迹，再
   训练一次并行的 Genome Head 与 pointer/copy 槽，不能拿 8 个样本的记忆结果晋级。
3. 离线训练多 token 草稿头并做自由滚动/拒绝位置回放；理论下界不够就停止，不改 C++。
4. 只为已经证实的能力岛训练 K 路由；`K=0` 为默认。
5. 三项都过门后再集成运行时，最后只做一次相邻速度 A/B 和一次 blind。
