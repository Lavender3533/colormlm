# v27 Tool Protocol Bus

## 目标

把 GLM-4.7 已经实测成立的工具协议互补能力蒸馏为 ColorLM 内部的小型末端能力头，而不是让
21GB GLM 整模常驻，也不是把 GLM 残差无条件注入普通对话。

当前完整16题中，v17为`10/16`、GLM为`9/16`。GLM相对v17的唯一稳定能力岛是工具调用：
`tools-read-file`和`tools-search-text`均从失败变为通过；同时它回归知识、代码和规划各一题。
因此v27只允许负责工具协议，禁止声称GLM整体强于v17。

## 结构契约

```text
v17 terminal hidden
→ rank-64 protocol projection
→ <=1024个候选token的稀疏logit修正
→ base logits
```

- 请求没有`tools`时物理旁路，不加载或不建立协议头节点。
- 请求携带工具schema时才允许启用；这属于显式输入模态，不读取用户文本关键词。
- 在线门最终仍由隐藏态置信度决定是否输出修正，no-op必须是显式竞争通道。
- 只学习工具名、参数名、参数值、JSON结构和结束标记；不得影响普通知识、代码或规划token。
- 训练、验证、测试按完整任务6/3/3隔离，不能按相邻token随机切分。

## 冻结门

`tool_protocol_gate_v1.json`在任何v27候选结果产生前冻结，共12个不同schema的工具任务；每题
使用足够输出预算，避免把单纯截断误判为不会调用工具。

冻结文件SHA-256：`a7b4d77e1c2550fa7958586f3050d7bb4ca48dbcfce56b942b7f9997b24587ac`。

教师准入：GLM至少`9/12`，并比v17至少多通过3题。未达到则停止v27，不拟合能力头。

候选晋级同时要求：

1. v17无工具请求逐token等价；
2. v27在3个留出工具schema上至少`2/3`，且不低于GLM教师；
3. 完整冻结16题至少保持v17的`10/16`，零净回归；
4. 两个原工具题至少新增1项通过；
5. 能力通过后才做一次相邻速度/资源检查。

## 最终结果

- v26已否决并释放服务。
- GLM完整16题供体屏幕已完成，证明工具维度`2/2`互补。
- 已为ColorLM运行图增加默认关闭的末层hidden与base logits一次采集通道；未启用v19输出头时，
  CNOB记录kind 4为base hidden、kind 1为base logits。v19原三张量记录契约保持不变。
- Vulkan Release增量编译通过；8119启动级烟测正确返回`OK`。两次记录均得到F32
  `[2048,1]` base hidden与F32 `[248320,1]` base logits，严格字节边界检查通过。
- GLM教师为`12/12`，v17为`11/12`；GLM只新增修复留出题`tool-ask-clarification`，零回归。
- 教师虽达到绝对分`>=9/12`，但只领先v17一题，未达到预先冻结的至少三题优势。
- v27按契约停止，不拟合、不实现协议头。末层hidden/logits采集设施继续保留为通用研究能力。
- 结论：v17在足够输出预算下已经能稳定构造一次工具调用；真实短板转移到工具结果回合后的
  继续/停止、跨步骤状态与规划，不再扫描工具JSON格式头。
