# v30 Dynamic Lexical Policy

v30验证“固定16行策略头不能覆盖新工具名、路径和值”的后续结构：

```text
terminal hidden -> L2归一化 -> rank-32左因子
当前tools请求的最近唯一token -> 基座embedding行 -> L2归一化 -> rank-32右因子
两者逐候选点积 -> clamp[-2,8] -> 原位修正最多256个logit
```

运行时权重只有`524416`字节。候选token由当前请求及已生成前缀提供，不做关键词任务分类；仅显式
`tools`请求建立策略图，无tools请求继续物理旁路。C++运行包、Vulkan图、动态I32/I64索引、mask和
API token历史输入均已编译并真实启动。

## 结果

- 旧v29数据上的回顾探针平均明显改善，但一个不可由输入唯一推出的测试目标回归，因此旧门按契约失败。
- 重新冻结12个目标可客观推出的独立任务后，178个token的NLL平均变化为`-0.67284`，12/12任务
  平均改善，0任务回归，动态目标覆盖`93.26%`，获得运行时原型资格。
- 真实生成A/B中，v17与v30均为`12/12`，去除随机tool-call ID后12题输出完全一致；平均decode速度
  `22.629 -> 22.214 token/s`，约`-1.83%`。

所以v30证明了动态低秩词汇残差可以在本机真实运行并跨新词元降低NLL，但没有证明实际能力超过v17，
不得替换正式v29，更不能称为通用智能提升。下一轮必须建立v17不能全过、但答案仍可由输入唯一推出的
新任务；本12题只保留为机制回归门，不再用于调参或晋级。

完整数字、哈希和声明边界见`runtime_gate_report.json`。
