# ColorLM v47 并行速度架构离线设计

## 0. 结论先行

v47不是运行时补丁，也不是论文复现。它把三条速度路线压缩成可审计的最小结构、解析成本和短门合同，供后续单独训练/实现时使用。本轮没有加载模型、没有启停服务、没有使用GPU，也没有改动本目录之外的文件。

当前证据给出三个强约束：

1. v24的`ngram-mod`在同一v17上总体`-0.72%`，且4题只有1题输出完全等价。多token验证若写入v17三层Gated DeltaNet state和L47 KV，就必须完整checkpoint/rollback；v47 A因此只读取v38主干的冻结多层特征，草稿侧不得写目标模型状态。
2. v17连续四层岛总权重`3,773,072,128`字节；v37把它叠到v36后能力短门零净增、速度成本`-20.60%`。B只能是约几MiB的局部共享循环，不能再搬一套四层供体。
3. v24中LFU97相对LRU少251次miss（`4.36%`、`423.56 MiB`上传），真实速度却`-0.22%`。C不能只追缓存命中率；必须同时优化SSD需求字节、PCIe上传、CPU/GPU执行位置和暴露等待时间。

因此，A/B仅通过结构与预算门，不代表已有可用权重；C的预声明4页预取在冻结回放上只把冷miss降低`2.56%`，未达`5%`硬门，保留为负结果，不进入运行时。

## 1. 共同状态与提交原则

所有候选都遵循“目标主干是唯一真值”：

- 温度0时，A的草稿必须由v38目标主干批量验证；拒绝仅提交接受前缀。
- A草稿计算、B局部循环均不得提前写KV、Gated DeltaNet recurrent state或专家缓存策略状态。
- B的K=0是逐位硬旁路：不加载循环权重、不创建循环图节点、不分配循环临时状态。
- C的预测失败只能增加等待；不得把miss映射到其他专家。正确专家必须在GPU、CPU精确路径或SSD读完后执行。
- 性能计数器不进入任何模型数学路径，开关关闭时应逐token等价。

## 2. A：EAGLE-3式多层特征直接多token草稿头

### 2.1 最小结构

基座固定为v38/v36坐标，宽度`d=2048`，从`L12/L24/L39`读取当前token的冻结hidden：

```text
h12 --P12(d×256)--+
h24 --P24(d×256)--+-- concat -- Q(768×d) --> z
h39 --P39(d×256)--+

z -- A(d×128) -- B1..B4(128×d) --> z1..z4
z1..z4 -- frozen lm_head(d×151936) --> 4个直接草稿token
```

每个未来位置独立得到一个latent，不在草稿侧递归写token状态。训练参数只包括多层融合、共享低秩A、4个位置B和4个位置向量；embedding与lm_head完全复用且冻结。最小实现不含新的attention/KV，也不触碰v17神经岛。

参数公式：

- 多层融合：`2*T*d*r_fusion`；
- 位置分支：`(K+1)*d*r_position + K*d`；
- 当前默认合计`4,464,640`参数，F16约`8.516 MiB`。

复用lm_head省掉约`d*vocab`级别的新参数，但4个位置仍需4次词表投影。本成本口径为`2.498 GFLOP/base-step`，约为假设3B active parameter基座单步的`41.64%`。在均匀接受率`0.65`、批量目标验证因子`1.35`的假设下，解析上界为`1.430x`；这是敏感性上界，不是预测。

### 2.2 训练合同

- 教师：冻结v38，采集同一序列的L12/L24/L39 hidden与未来1..4 token。
- 损失：4个位置的token CE；位置越远权重不得高于位置1。可增加hidden回归，但不能用其替代token CE。
- 数据隔离：训练/校准/最终短门按任务族分割；最终短门不能用于选择K、rank或阈值。
- 验证：一次目标forward验证4个草稿；发生第j位拒绝时只提交`[1,j)`，再提交目标第j位。
- 状态：草稿头只读已提交hidden；目标验证使用临时sequence branch，接受后原子提交，拒绝后丢弃临时branch。

### 2.3 晋级合同

离线预算：参数不超过10M、F16不超过24MiB、解析上界至少`1.10x`。运行晋级还必须在至少32条冻结任务上：温度0输出与无草稿目标逐token一致，接受率至少60%，同机端到端速度至少`1.10x`，并分别报告文本/代码/工具任务的接受长度分布。v24 n-gram负结果禁止用“平均输出相似”绕过逐token等价门。

## 3. B：Penelope/Mixture-of-Recursions式局部潜在循环

### 3.1 最小结构

在L24之后设置一个只处理当前token latent的共享残差单元：

```text
router(h24, workload) -> K ∈ {0,1,2,3,4}
x0 = h24
x(k+1) = xk + Wout( SiLU(Win( RMSNorm(xk) )))
输出 = xK
```

`Win:2048→512`、`Wout:512→2048`在所有循环共享。K路由器为`2048→64→5`，采用预算约束的直通/分类训练；推理取确定性argmax并受全局预算钳制。当前参数`2,228,549`，F16约`4.251 MiB`。

这个设计只借鉴“局部latent重复计算”和“按token分配不同递归深度”的思想，不复制任何论文训练配方。循环会增加计算，本身不是速度机制；它只有在以下两种情形才有意义：用很小的共享块替代更贵的固定层，或用少量K>0恢复A/C激进速度策略损失的质量。未满足其一时应直接选K=0。

### 3.2 动态K合同

路由输入由当前token hidden统计与只读工作量信号组成：归一化残差能量、前后层hidden差、草稿拒绝EMA、工具协议标记、当前CPU/GPU队列压力。禁止读取未来token或最终短门标签。

建议训练目标：`quality_loss + lambda_compute*K + lambda_budget*max(0, batch_mean_K-budget)`。推理约束：

- 简单/高置信token优先K=0；难token最多K=4。
- 预设分布`[0.35,0.25,0.20,0.12,0.08]`仅用于成本分析，均值`1.33`，不是已观测路由。
- 每个请求报告K直方图、mean/p95、按任务族质量差和路由校准。
- K=0占比至少25%、mean K不超过1.5；超预算时从最低边际收益token开始降K。

循环禁止KV写、recurrent state写和缓存策略写。若未来要跨token递归，必须新开版本并先解决v24已暴露的checkpoint/rollback问题。

### 3.3 晋级合同

结构门只检查K域、硬旁路、权重共享和预算。真正晋级必须在冻结质量门零回归，并相对等质量固定计算基线获得至少`1.05x`端到端速度。仅报告循环块FLOPs很小不能算通过。

## 4. C：DALI式残差预取与工作量感知分层缓存

### 4.1 三层与两条预取队列

- GPU hot：每层32页，直接运行专家GPU内核。
- CPU warm：每层128页，可选择CPU精确执行或上传GPU。
- SSD cold：剩余精确专家页，按页读取。

两条队列分开计费：

1. `Q0 residual-demand`：当前层router已给出top-10后，计算`requested-GPU-CPU`，立刻异步读精确残差页；与shared expert、其他已命中专家和可独立CPU工作重叠。这是“残差预取”，不会预测错误专家。
2. `Q1 next-step-predictive`：用训练段的同层token转移统计，预测下一token最多4页，只放CPU warm。错误预取可被淘汰，且字节必须单独报告。

离线工具不伪造并发时间，只报告需求SSD字节、预测SSD字节和解析重叠下界；真实的队列重叠必须由后续运行时trace证明。

### 4.2 CPU/GPU动态分配

每页维护衰减频率、最近使用、下一步转移票数、页字节、上传成本和GPU队列压力。价值近似：

`benefit = predicted_reuse * (cpu_or_ssd_latency - gpu_latency) - upload_latency - eviction_externality`

当前已激活页始终精确执行，但不必全部上传：当GPU已满且候选价值低于最弱GPU页加`promotion_margin`时，本token走CPU精确路径；否则上传并把被逐页的热度较低页降到CPU warm。这比纯LRU/LFU多了“执行位置”和“搬运是否值得”的决策维度。离线回放器以衰减工作量分数近似该决策，并显式报告`cpu_executions`与`gpu_uploads`。

### 4.3 工作量感知淘汰为何可能优于LRU/LFU

LRU只看最近时间，突发扫描会污染GPU；LFU97看衰减频率，但不知道下一步转移、页大小、上传成本和CPU/GPU队列。v47的优先级同时看：

- 预测复用概率与层间/同层转移；
- 专家页字节和SSD/PCIe成本；
- 当前页能否在CPU精确执行而不上传；
- 当前token pinned页不可淘汰；
- 预测页未命中前不污染GPU，只进入CPU warm；
- 误预测字节、有效预取率和暴露等待作为独立负债。

因此它的目标不是“命中率数字更高”，而是在较小RAM常驻下最小化`暴露SSD等待 + PCIe上传 + CPU回退计算 + 同步尾延迟`。只有同预算回放和真实运行都胜出，才能说优于当前LRU/LFU。

### 4.4 本轮冻结回放

输入是v24真实路由dump：4层各128 token、每token top-10。每层前64步只训练转移统计，后64步冷启动回放；预取页数4在运行前写入manifest。GPU/CPU容量对LRU、LFU97、v47完全一致。

聚合2560次请求：

| 策略 | GPU命中 | CPU warm命中 | 冷miss | 需求SSD | 预测SSD |
|---|---:|---:|---:|---:|---:|
| 分层LRU | 599 | 788 | 1173 | 1979.44MiB | 0 |
| 分层LFU97 | 724 | 668 | 1168 | 1971.00MiB | 0 |
| v47工作量预取 | 694 | 723 | 1143 | 1928.81MiB | 195.75MiB |

预声明回放得到冷miss 1143，相对LRU只降`2.56%`，有效预取精度`23.28%`，且预测额外读`195.75MiB`；没有过5%冷miss门，总SSD字节也未占优。动态放置把GPU上传从1961次降到519次，但转为1347次CPU精确执行，只有真实时延才能判断是否划算。禁止在同一后半段扫描预取页数后把最好值写成留出结果。

## 5. 实施分期

1. A先做hidden采集与离线训练，不接运行时；达到接受率门后才实现临时sequence branch验证。
2. B先训练K固定为0/1/2/4的质量-成本曲线，再训练动态路由；若没有等质量替代收益则终止。
3. C先另采独立路由trace并冻结预取参数；只有同预算回放通过才实现Q0，最后才实现Q1。
4. 三条线分别过门，不同时集成。A+B、A+C的交互会改变接受率/路由分布，必须重新冻结组合门。

## 6. 声明边界

“EAGLE-3式”“Penelope/Mixture-of-Recursions式”“DALI式”只描述设计灵感。架构、量化、运行时、硬件和训练数据均不同，论文速度不能直接复现。本目录的解析上界、短路由命中和自检只能支持离线工程决策。
