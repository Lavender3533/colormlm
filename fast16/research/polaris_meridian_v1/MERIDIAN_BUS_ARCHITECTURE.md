# 北极星 Meridian Bus：巨型模型器官移植架构 v0.1

## 目标

北极星不再把“小模型蒸馏”当主路线。目标是让本地主干保持可交互速度，同时把 300B--700B+ 开源供体的**功能电路**做成 SSD 可分页器官。这里的最小移植单位不是“一个看起来很聪明的 tensor”，而是：

```text
原生状态锚点 + 原生路由轨迹 + 必需专家页 + 状态接口 + 可关闭残差 + 反事实收益证据
```

单个 expert、router、embedding 或 MTP 头只算组织切片；缺少原生状态和连接关系时，不算能力器官。

## 两个平面与当前主线

为了避免又回到“给小主干贴很多补丁”，北极星分为两个平面：

1. **质量主脑：DeepSeek 原生稀深 S14。** 保留 DeepSeek 自己的 tokenizer、embedding、4096 坐标、mHC、attention、router、MoE 与 lm head，只执行 14 个预注册 residual block。静态预算为 52,231,273,716 B，粗估每 token 活跃 4.59B 参数。它最符合“从几百 B 模型切出可运行新架构”的要求，也是当前唯一先做的质量实验。
2. **Meridian Bus：专项器官层。** 只有 S14 Gate 1/2 有基础语言能力后，才让 Kimi 前端/视觉、GLM 长上下文等器官通过经穴图谱进入八个能力站。

DeepSeek L39--L42 状态采集既服务于连续皮层/门户证伪，也为 S14 的原生层影响、route 热集合与分页预算提供显微镜；它不是让 v38 永久充当小主干。

## 为什么引入“八卦”和“五行”

它们只作为工程命名与拓扑启发，不作为模型有效性的证据。

### 八个能力站（先天八卦）

| 站 | 工程能力 | 首选供体方向 | 当前状态 |
|---|---|---|---|
| 乾 | 深推理、总规划 | DeepSeek-V4 / GLM-5.2 | 等待原生状态 |
| 坤 | 知识整合、长期记忆 | 主干 + 检索总线 | 架构位 |
| 震 | 编程、工具动作 | Kimi K3 文本电路 / 强代码 donor | 等待 route trace |
| 巽 | 长上下文、跨层检索 | GLM IndexShare 拓扑 | 只借机制 |
| 坎 | 调试、风险、失败恢复 | DeepSeek 反思轨迹 | 等待原生状态 |
| 离 | 视觉、网页理解 | Kimi K3 MoonViT-V2 | 可独立切，缺 1024→2048 接口 |
| 艮 | 停止、验证、no-op | 北极星本地 verifier | 必须常驻 |
| 兑 | 对话、表达、对齐 | Kimi/GLM 后训练电路 | 能力分布式，不能靠单专家 |

这八站不是把 prompt 用关键词硬分类。在线路由输入只能来自连续隐藏态、置信度、预算、器官驻留状态和已冻结的反事实收益统计。

### 五段循环（五行）

| 相位 | 作用 | 对应计算 |
|---|---|---|
| 木 | 发散与计划 | 生成候选路径，允许调用乾/巽 |
| 火 | 执行与表达 | 调用震/离/兑产出动作或 token |
| 土 | 汇总与记忆 | 把多路状态压回主干工作空间 |
| 金 | 裁剪与验证 | 艮/坎否决冲突、错误工具参数和低收益器官 |
| 水 | 检索与不确定性 | 读取 SSD 状态锚点、上下文证据和冷器官页 |

“相生”是正常数据流：水→木→火→土→金→水；“相克”实现为冲突边：验证抑制执行、预算抑制发散、证据不足抑制知识注入。它最终应是一个有 no-op 的稀疏状态机，而不是玄学打分。

## 核心创新：经穴状态图谱

跨模型 hidden 宽度和坐标不一致，是直接塞专家失败的根因。无大训练版本先不用全局 4096→2048 或 7168→2048 神经桥，而是采集成对“经穴”：

- `a_j`：同一冻结前缀下的北极星 hidden；
- `d_j`：巨型供体的原生 hidden、router 和器官输出；
- `benefit_j`：强制 no-op 与强制器官路径的 next-token NLL 差；
- `payload_j`：该点真正需要的专家页与状态契约。

运行时只在 `h` 落入已验证邻域时激活：

```text
w_j = softmax(cos(h, a_j) / tau)
confidence = max_j cos(h, a_j)
if confidence < theta: route = no-op
else: donor_state = sum_j w_j * d_j
```

这不是大模型训练，而是状态采集、近邻检索和局部插值。优点是成本小、SSD 友好、错误时能退回主干；局限是只在图谱覆盖到的局部任务上泛化。经穴数量扩大后，才可能逐步形成“百花齐放”的器官库。

## 器官执行契约

每颗器官必须拥有以下六层接口：

1. **身份层**：供体仓库、固定 revision、license、tensor SHA-256；
2. **神经层**：供体原生输入 hidden、层号、norm、router、残差语义；
3. **载荷层**：Range 列表、量化 ABI、SSD 页大小、热/温/冷驻留；
4. **翻译层**：成对状态锚点或已验证桥；没有翻译证据则禁止接主干；
5. **路由层**：连续特征、no-op、预算和冲突仲裁；
6. **证据层**：预冻结任务上的反事实 NLL、实际正确性、速度和回退等价。

在线式：

```text
h' = h + sum_i alpha_i * residency_i * confidence_i * safety_i * P_i(organ_i(B_i(h)))
```

约束：

- `alpha_i = 0` 时物理不加载，逐 token 精确退回主干；
- 默认 top-1，只有互补证据充分时才 top-2；
- 每个 token 有 I/O 和 MAC 预算，超预算先 no-op；
- 未通过反事实门的器官不能因为“输出变了”而晋级；
- 单专家非零输出、合成 hidden、自报身份都不是能力证据。

## 巨型供体手术顺序

### P0：DeepSeek-V4 原生稀深 S14 + 状态采集

先在原生执行器中跑预注册 S14 的 4 题早停门，同时在可用完整 forward 中采 L39--L42 状态和 top-6 router。理由不是它最容易，而是 304B/13B-active、官方层边界清楚，能在不跨坐标的前提下测试巨型模型切片是否仍保留质量。当前 52.23GB 物理预算与采集协议已通过静态/CPU 合成自检；Ascend 原生 runtime adapter、真实 S14 forward 与质量结果尚未完成。

### P1：Kimi K3“前端电路”定位

如果“前端”指网页代码能力，不能下载 MoonViT 当答案；MoonViT 只负责看图。正确做法是在冻结的 HTML/CSS/JS、工具调用、截图还原任务上运行 K3，采集各层 router 轨迹，寻找跨任务重复出现且有 NLL 正收益的**专家社区**。预计移植单元会跨多层，而不是一颗专家。

如果“前端”指看懂网页截图，则 K3 的 802,428,928 B MoonViT-V2 是当前唯一功能边界清楚的巨型器官，后续只需解决视觉 token 到北极星 2048 工作空间的接口。

### P2：GLM-5.2 长上下文拓扑

不搬 GLM indexer 权重，先在北极星原生 attention/检索总线上复现“一个索引决定跨四层复用”。这是速度结构，不是假装搬来 GLM 知识。

### P3：第二供体与冲突仲裁

只有 S14、DeepSeek 连续皮层探针与 Kimi 各自在冻结任务上单独胜出，才允许同一能力站竞争。五行相克表实现冲突约束，艮站 verifier 拥有最终 no-op 权。

## 近期能交付的成果

1. S14 原生稀深旗舰的 4 题早停质量结果；
2. DeepSeek 原生状态采集文件，而不是整模型常驻；
3. 第一版经穴图谱：任务前缀→主脑状态→供体状态→route→NLL 收益；
4. DeepSeek L42 单专家+router 行的 13,377,540 B 分页 ABI 样本；
5. Kimi K3 前端任务 route-trace 契约；
6. 关闭等价、速度预算和多能力短门。

## 不夸大的可行性结论

这条路线确实不同于普通蒸馏：它研究的是运行时状态寻址、稀疏器官分页和跨模型局部坐标拼接。但“不训练”不会让接口问题自动消失。成对状态采集和局部插值是最低成本的替代品；若它在留出任务上不能泛化，就必须承认该器官只能做记忆补丁，不能称为通用能力移植。

北极星可以允许最终磁盘模型达到 50--70 GB，但每 token 实际读取量仍必须小。决定本地速度的不是磁盘总容量，而是每 token 激活多少页、跨 PCIe/内存搬多少字节，以及 verifier 让多少无效器官保持休眠。
