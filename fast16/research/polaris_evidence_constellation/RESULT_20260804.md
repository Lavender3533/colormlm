# 证据耦合星座动力学 v0 首次结果

日期：2026-08-04
性质：纯 CPU、秒级、冻结夹具结构门

## 结果

- 定向单元门：`6/6` 通过；
- 冻结场景：`3/3` 通过；
- 场景断言：`16/16` 通过；
- 模型启动：`0`；
- GPU 运行：`0`；
- 训练：`0`。

### Java/PHP

Java 与 PHP 对同一 `backend.stack` 的异值写入生成两个分支。环境未确定时，
所有存活分支的交集先提交布局和 API 合同，不提交后端。PHP 证据闭合后可局部提交；
同一 Composer 来源组随后回报失败时，新回执取代旧回执，只回滚 PHP，已提交的布局/API
保留。JVM 后续就绪时 Java 分支恢复并提交。

### 截图网页

全表格、全卡片和“桌面表格＋移动卡片”是三个真实分支，不做概率平均。数据字段与交互
合同作为分支交集先提交。桌面/移动浏览器回执同时否决两个全局布局，只保留第三个
混合分支。这证明“综合方案”可以作为新世界出生，不需要把两个冲突答案混成一个向量。

### 相反事实

两个大模型的相反输出生成两个分支。即使某个神经提议探索优先级更高、或同一器官重复
提议，没有外部回执时仍不会提交。真实 runtime probe 到达后，匹配候选获得认证，相反候选
被否决，答案才进入已提交子图。

## 证明了什么

1. “冲突分支，不平均”在一个小内核中可执行；
2. “存活分支交集＋证据闭合”可作为局部提交规则；
3. 探索优先级与事实认证可以分离；
4. 同一来源组的重复回执不会制造虚假多数；
5. 已提交的依赖失效时可局部回滚，无关锚点和公共子图保留。

## 没有证明什么

- 夹具提议由人工写入，没有证明 v38/v17/S14 会自主产生好候选；
- slot、依赖和 requirement 目前是显式类型，没有学习语义兼容性；
- 分支数可能随冲突组合爆炸，v0 没有实现支配集裁剪或 SSD 休眠；
- 证据可靠度与独立来源组由合同给定，尚未校准；
- 结构通过不是模型能力、速度、意识或论文新颖性证据。
